## Milestone 1 — design evidence

Refer to the repository root `README.md` for users, roles, user stories, workflows, initial operation inventory and example JSON.

Selected scope for first implemented workflow:
1. Admin authenticates with a bearer token.
2. Admin creates a substitute request with subject, grade, date and optional time slot.
3. Backend validates the request and persists it through SQLModel.
4. Admin retrieves the request and can modify it while still open.
5. A teacher can apply to an open request; admin can approve an application.

## Milestone 2 — API contract and implementation

FastAPI exposes generated OpenAPI at `/openapi.json`, with interactive documentation at `/docs`. Start the server from the `backend` directory.

| Method | Path | Contract / implementation |
| --- | --- | --- |
| GET | `/api/v1/requests/` | Admin list; `RequestRead[]` |
| POST | `/api/v1/requests/` | Admin create; JSON `RequestCreate`, 201 `RequestRead` |
| GET | `/api/v1/requests/{request_id}` | Admin read; 200 `RequestRead`, 404 |
| PATCH | `/api/v1/requests/{request_id}` | Admin edit open request; `RequestUpdate`, 409 for closed/filled |
| DELETE | `/api/v1/requests/{request_id}` | Admin delete open request with no applications; 204, 404, 409 |
| GET | `/api/v1/requests/open` | Teacher list of open requests |
| POST | `/api/v1/requests/{request_id}/apply` | Teacher application, 201 |
| PATCH | `/api/v1/applications/{application_id}/approve` | Admin approval and auto-rejection of other pending applications |

Example POST JSON (replace date with a date in the future, and subject_id with an existing subject):

```json
{
  "date": "2026-12-01",
  "grade_level": "3a",
  "subject_id": 1,
  "time_slot": "08:00-10:00",
  "note": "German lessons"
}
```

Expected result: HTTP 201 and a JSON object including `id`, `status: "open"`, `created_by`, date and grade.

Negative examples: past date / invalid grade / invalid time slot / subject ID <= 0 => HTTP 422 for schema validation; nonexistent subject => HTTP 400; unauthenticated call => HTTP 401; forbidden role => HTTP 403; nonexistent request => HTTP 404; edit/delete of filled request => HTTP 409.

Status: **Code committed to development branch. Not yet runtime-verified.** Check that autogenerated OpenAPI and all application flows match the implementation during coaching preparation. The contract is generated from FastAPI routes and Pydantic models; this table is a human-readable inventory, not a separate maintained YAML file.

## Decisions / known limitations

- Reuse FastAPI + SQLModel + SQLite from the target repository; do not overwrite it with the earlier NiceGUI monolith.
- API request payloads should be JSON body models, not implicit query parameters.
- Prioritize core `SubstituteRequest` CRUD before expanding the frontend.
- Current legacy expiration policy deletes expired requests; whether to archive them for an audit trail needs a team decision.
- The service checks application status before approval but concurrent approvals need additional transactional/database protections before a production claim.
- Review upload security, JWT secret configuration, and demo credentials before final submission.
- The source and target are both team/student work; document reused work and individual contributions transparently.

## Local demo administrator

The current FastAPI startup creates database tables but does not seed an administrator. Public `/auth/register` creates a teacher role, not an admin.

A development-only bootstrap script is available at `backend/scripts/create_local_admin.py`. From `backend/`, after activating the Python virtual environment:

```powershell
git pull origin feature/milestone1-2
python scripts/create_local_admin.py
```

The script prompts for an email, name and password, securely hides the password input, hashes it with the application's normal password hashing utility, and stores the new account in the local ignored SQLite database. It refuses to overwrite an existing account with the same email and requires a password of at least 12 characters.

In Swagger UI use `POST /api/v1/auth/login` with the admin email entered as **username** and the newly chosen password as **password**. Then authorize using the returned JWT. Do not paste passwords or JWT tokens into GitHub, chat, screenshots or documentation.

This is a local-development convenience only, not production user provisioning. The existing hard-coded JWT signing secret in `backend/core/security.py` still needs to be replaced by secure environment configuration before final submission.


## Local admin hashing dependency fix

If `python scripts/create_local_admin.py` fails with `AttributeError: module 'bcrypt' has no attribute '__about__'` or bcrypt's 72-byte-password ValueError inside Passlib initialization, the previously unpinned bcrypt dependency is incompatible with passlib 1.7.4. `backend/requirements.txt` now pins `bcrypt==4.0.1`. In an activated virtual environment run `python -m pip install -r requirements.txt` and verify `python -m pip show bcrypt` reports 4.0.1. Retry local admin setup. The script now refuses passwords longer than 72 UTF-8 bytes. Do not commit credentials or JWTs.
